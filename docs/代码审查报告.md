## 1. 关键路径审查

### 1.1 身份加固（B1/B2/§2.4）——正确性 ✅
- `identify()` **仅首次**绑定 `secret`，且只接受 `^[0-9a-f]{64}$`；后续请求带不同 key 不覆盖。
- `verifyKey` 先做格式白名单再 `timingSafeEqual`，并 try/catch 兜住——**不会因畸形 key 抛异常**（同 P0-1 教训）。
- `rename/setAvatar` 对已绑定会话强制校验；**未绑定放行**（兼容老会话与账号），且 `secret` 在 `privacy.js` 黑名单。
- 账号身份（token）在协议层被显式排除出 `key` 绑定路径（`identifyMeta.key = null`），避免"账号会话被绑游客 key"。
- B2：迁移凭据校验**保留**在"目标 id 已是注册账号则拒绝"守卫之后；拒绝路径有审计。

### 1.2 §3.1 harness —— 定位与修复可信 ✅
- 复跑证实：修好 harness（跨平台杀进程组 + `os.tmpdir()` + 退 出码校验）后，本机 16/0（此前 13/3）。
- 附带发现并修复 `e2e-freeboard.js` 的**同源**问题（Windows 清理 + 清理巡检写死 60s）→ 40/0。
  ⚠️ 该修复过程中观察到**早前运行遗留的孤儿 `node server.js` 占端口**会污染结果——已在收尾清掉；
  提示：跑自带服务器的 e2e 前应先确认无遗留服务进程。

### 1.3 §3.2 回位收窄 —— 语义正确 ✅
- `reconnect`/`bindToActiveGame`：`preferRoomId` 存在时**只在房内**回位；未找到即返回未命中，**不跨房兜底**；
  未提供 `preferRoomId` 时保持原跨房行为（兼容）。三条单测覆盖（房内命中 / 存在但不在其中 / 未给参数）。

### 1.4 §5.1 / §5.2 性能 —— 收益可量化 ✅

### 1.5 §7.2 / §4.3 —— 可用 ✅

### 1.6 §4.2 服务端拆分 —— 行为等价性 ✅（第二轮，含一处真缺陷的发现与修复）
- **加载顺序无环**：`protocol.js` 的 handlers 是 mixin（无相互 require）；`tournaments/` 的
  `store → rules → swiss-flow → bracket → lifecycle → archive → view` 由脚本拓扑排序验证，**无环**。
- **`protocol.js`**：`_routeInner` 的 28 个 case 体搬走后，`tests/messages.test.js` 的
  「C2S 契约表 ↔ switch 分支」**双向一致性检查仍以 `protocol.js` 源文件为基准**（刻意保留 switch）——
  拆分支未削弱这条护栏，这是本次拆分最容易被做坏的地方，已确认完好。
- **`tournaments.js`**：59 个顶层段按行区间**原样搬移**；对外 `module.exports` 块**原文照搬**，
  41 个导出符号逐字一致（脚本断言 + 人工核对）。
- **⚠️ 拆分中发现并修复一个真缺陷**（若只做静态搬运就会带出去）：
  `cache` / `matchFactory` 是 `let` 可变量，`module.exports = { matchFactory }` 导出的是**取值快照**——
  跨模块解构后永远拿到 `null`。表现为瑞士制/重赛建不了局、**21 个单测转红**。
  修复：`store.js` 改为**访问器导出**（`get matchFactory()`），消费侧用 `store.matchFactory` 属性访问。
  → 已写入 `store.js` 注释，作为「拆分可变量」的通用注意事项。

## 2. 发现的问题与建议

### 🟡 次要（4）

1. **`refreshCache()` 的"丢弃内存改动"契约是隐性依赖**（`src/ratings.js`）
   已在 JSDoc 写明契约、并在 `accounts.migrateGuestData` 前 `flush()`；但**任何新调用点若忘 `flush` 会静默丢数据**。
   → 建议：后续把 `refreshCache` 更名/拆分语义（如 `reloadFromDisk()` 强制先 flush，`discardAndReload()` 明确丢弃），
   让"丢数据"这件事从**默认**变成**显式选择**。

2. **会话名缓存 5s 最终一致**（`src/ratings.js`）
   `invalidateSessionCache()` 目前**只挂在排行榜读路径上被调用测试**，生产写点（`auth.rename`、封禁、迁移）
   **未接入**。改名后管理员用户列表最多 5s 才更新。
   → 建议：在这些写点调用 `invalidateSessionCache()`（本轮为控制改动面未接入）。

3. **`_kifCached` 返回缓存数组本身**（`src/rooms/state.js`）
   命中时返回缓存引用；当前调用方均只读，安全。若将来有代码**原地修改** `state.movesKif` 会污染缓存。
   → 建议：需要可变时返回浅拷贝，或在类型层固化"只读"。

7. **跨模块共享的 `let` 状态必须以访问器暴露**（`src/tournaments/store.js`）——见 1.6：
   本轮已修 `matchFactory`，但同类的 `cache` 仍是「内部变量 + `getCache()`」两套读法
   （外部应一律 `getCache()`，不要解构）。→ 建议：后续把 `cache` 也收敛成单一读法，杜绝再踩。

### 🟢 观察 / 既有（3）

4. **`identify()` 的 `_lastPersist` 是模块级 Map，随进程存活**（`src/auth.js`）——大流量下单进程条目数 = 活跃会话数，
   可接受；但进程重启后首次连接必写一次（预期行为）。
5. **6 条 eslint warning 为既有**（`no-unused-vars`：`public/js/play.js`、`scripts/e2e-*` 等），非本轮引入。
6. **类型护栏为渐进式**：`checkJs:false` + 按文件 `// @ts-check`——**新增模块不写 pragma 就不会被检查**，属有意取舍。
