## Bug 1｜棋驹出阵没有升变提示 + 升变合法性未校验

- **根因**：`src/game.js` `candidateMovesFrom` 只判断**终点** `inPromotionZone(m.to.y)`，漏了**起点**——`from` 在敌阵、`to` 在阵外（出阵）时不提供升变；且 `shogi.js` 的 `move()` 给 `promote` 即无条件升变、不做合法性校验。
- **修法**：`canPromote` 改为 `inPromotionZone(起点) || inPromotionZone(终点)`；新增 `promotionAllowed()` 并接进 `isMoveLegal()`，无权升变（金/王/已成子，或起终点均在阵外）请求升变一律拒绝（`move_invalid`）；导出 `isMoveLegal` 供单测。
- **测试**：`tests/game.test.js` 新增 7 条（出阵成/不成、阵外→阵外、阵外→阵内、金/王/成駒永不升变、强制升变拒绝、`isMoveLegal` 权威、`applyMove` 拒绝非法 +）。前端升变弹层由服务端 `legalTargetsBySq` 驱动，服务端补齐即可弹出，无需改前端。

## Bug 2｜加入房间后显示的房间号不正确

- **复核结论**：**文档化场景在当前版本已不可复现**——`public/js/play.js` 的 `request_state` 已带 URL 里的 `roomId`，服务端 `reconnect`/`bindToActiveGame` 已按 `preferRoomId` 优先绑定、且 `_autoLeaveAllRooms` 三段式清理已生效；实测「建房→凭码加入」「B 先玩过别的房再加入新房」「漏带 roomId」三种路径，**四方房号一致、均显示新房号**。
- **修法**：**未改业务代码**（避免无谓改动）；按外包书要求补 e2e 固化防回归。
- **测试**：新增 `scripts/e2e-room-code.js`（12 项，已注册进 `e2e-all.js`）。

## Bug 3｜改名/注册后个人页查不到棋谱；管理端显示「用户不存在」

- **根因 A（幽灵游客会话，必修）**：`src/accounts.js` `migrateGuestData` 把游客会话**复制**到账号 id 却**从不删除** `sessions/<guestId>.json` → 同一人在 `listSessions()`/管理端出现两条（幽灵游客 + 账号）。
  **修法**：迁移成功后删除旧游客会话（新增 `auth.removeSession`，`migrateGuestData` 调它；`account.guestId` 仍保留用于清理/追溯）；防重复迁移守卫与审计日志不动。
- **根因 B（管理端 id 形态）**：`src/http/routes/admin.js` 直接用 `:id`，而 `auth.adminRename/banPlayer/…` 要求 24 hex 会话 id——token 形态会被拒 → 「用户不存在」。
  **修法**：新增 `resolveAdminUserId()`，统一走 `resolvePlayer`（令牌→accountId），并对「是账号但缺会话」补建会话；全部用户管理接口改用它。
- **根因 C（前端着色）**：`public/js/profile.js` 用 `r.playerIds.b === guest.id`，账号的 `guest.id` 是令牌而棋谱存 accountId → 恒 false，胜负着色全错。
  **修法**：改用解析后的 `viewedId` 比对。
- **测试**：`tests/accounts-migration.test.js`（3 条：幽灵会话消除、守卫不破、`removeSession` 幂等）；`scripts/e2e-admin-identity.js`（10 项：幽灵行消失 + 按 id/令牌均可改名校验封禁）。

## Bug 4｜改名/注册后会自己匹配到自己

- **根因**：`quickMatch` 的守卫**只认 `playerId` 相等**；注册后 `playerId` 由 guest id 变成 account id，旧队列项（旧 id）与新连接（新 id）被当成两个不同身份 → 自己和自己配对。
- **修法**：引入**身份组**判定（`_identityGroup` / `_shareIdentity`）——账号与其**升级来源 guestId** 视为同一人（依据 `accounts.listAccountsRaw().guestId`，**不按 IP**）；入队前先清理失效（已断连）的队列残留；入队守卫与配对安全网都改用身份组。（断线清队列本已由 `_unbindClient` 覆盖。）
- **测试**：`scripts/e2e-match-selfplay.js`（7 项：同 playerId 双连接被拒、注册前后双身份不成局、断线队列无残留、不同玩家正常配对）。

## Bug 5｜棋驹声音没有播放

- **根因**：`public/js/sound.js` `playFileSound` 破坏自身「失败即降级」契约——`const p = a.play(); return true;` 把 reject 用 `.catch(()=>{})` 吞掉又无条件返回 true，调用方 `if (playMoveFile(...)) return;` 于是**永不回退合成音**，文件 404/被拦时完全没声音。
- **修法**：回退做实——`playFileSound(path, opts, onFail)` 在 `play()` 同步抛错时返回 `false`（调用方立即回退），在 Promise reject / 元素 `error` 事件时经 `onFail` 回退；`playMove/playCapture` 抽出 `synthMove/synthCapture` 作回退并传入；两条失败路径只回退一次。
- **测试**：`tests/sound.test.js` 新增 1 条（`play() reject` 与 `error` 事件两条失败路径都回退、正常播时不重复）。
