### 0.2 环境与命令

```bash
npm install
npm test               # 单元测试（Node 内置 node --test，纯函数，不需起服）
npm run lint           # eslint；必须是 0 error
npm run e2e            # 起隔离实例（临时 DATA_DIR + ADMIN_PASSWORD）跑全部脚本并汇总
npm run e2e -- --keep  # 排障：保留临时数据目录

npm run backup         # 备份 DATA_DIR
npm run pack           # 生成部署产物 → github-upload/ 目录
```

⚠️ **部署镜像里没有 `tests/`、`scripts/`、eslint 配置、`docs/`**：
在镜像里跑 `npm test` 会得到 **"0 个测试通过"的假绿**、`npm run lint` 直接报错。
要跑这些请回开发仓库（这条也已写进 README，见审查项 P2-5）。

## B 类：安全与身份模型（**最难，建议交给最有经验的人**）

### B1 游客持有证明（ROADMAP 13d）

- **问题**：`resolveOwner()` 解决了"注册账号必须凭令牌"，但**游客仍是"知道 id 即身份"** ——
  游客 id 一旦泄漏（出现在 URL、日志、截图里），别人就能以他的身份读写数据。
- **难点**：这是**身份模型**改动，且**必须兼容老浏览器**（不能一步收紧，否则现有游客直接丢身份）。
- **设计草案已写好**，见 `docs/ROADMAP.md` §"13d / 13e 的设计草案"，要点：
  游客会话里生成**不下发**的 `secret`（32 字节 hex，存 `sessions/<id>.json`，
  `publicInfo`/`playerCard`/`profile` 都要拦住，参照 `stripPrivate`），前端 `localStorage` 存、
  请求带 `key`，`resolveOwner()` 对游客 id 也要求带对 key。
  ⚠️ **两步走**：先只对**写操作**强制（读先放行 + 记日志统计"没带 key"的比例），下个版本再对读强制。
- **涉及**：`src/auth.js`、`src/http/context.js`、`src/protocol.js`、`public/js/api.js`/`profile.js`/`history.js`。
- **验收**：新增 e2e —— ① 不带 key 的游客 id 写操作必须 403；② 带对 key 正常可用；
  ③ 兼容期读操作不被打断（日志有比例可看）。

### B2 迁移凭据（ROADMAP 13e）

- **问题**：P0-3 当时只做了**最小修复**（`register` 拒绝"已是注册账号的 id"作 guestId）。
  完整方案是"**只有数据的持有者**才能把该游客 id 迁移到自己账号"。
- **做法**：复用 B1 的 `secret` 作 `migrationKey`，`register` 时校验。
- **验收**：e2e —— 拿别人的 guestId 迁移**必须失败**，自己的成功。

### B3 启动安全自检 fail-fast + `SECURITY.md`（审查报告「阶段 2」）

- **现状**（已核实，别误判）：
  - 密钥已是安全的 —— `SESSION_SECRET` 未配置时**首启生成随机密钥并落盘** `data/secret.json`，
    同时打印一条"建议显式配置"。**不需再修这条**（P0-2 已修）。
  - 固定默认管理口令已在 P1-2 删除（`src/admin.js:29`），也不需再修。
  - 缺的是**没有 fail-fast**：缺配/弱配时仍照常启动，只在日志里提示。
- **要做**：加 `REQUIRE_STRONG_SECRETS=1` 开关，置位时**启动即失败**（适合生产/容器编排）；
  补 `SECURITY.md`（漏洞上报渠道 + 部署安全清单）。
- **量级**：半天以内，风险低，但属安全面，建议与 B1/B2 同一人做。
