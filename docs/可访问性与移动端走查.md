>
> 本文分两部分：**已自动化的部分**（有测试守护，改坏了会报红）与**必须真机/人眼的部分**（清单化，逐项勾）。

## 一、§6.3 可访问性（a11y）

### 1.1 已落地的改造

| 项 | 实现 | 自动化守护 |
|---|---|---|
| 弹层语义 | `#promoteOverlay`（对局页）、`#userDetailModal`（管理页）、`#createModal`（赛事页）均加 `role="dialog" aria-modal="true" aria-label="…"` | `tests/a11y.test.js` 静态断言 |
| 弹层焦点 | 打开时焦点移入弹层、关闭时归还触发者（`public/js/a11y.js`） | `a11y.test.js` 行为断言（真调 + 真发 Esc） |
| Esc 关闭 | 已注册 `onClose` 的弹层可按 Esc 关闭；**升变弹层不注册**（重要决策，不该被 Esc 随手取消） | `a11y.test.js` |
| 棋盘键盘操作 | 棋盘容器变为可 Tab 聚焦的 `role="grid"` 部件：**方向键**移动活动格、**Enter/Space** 选择/落子、**Esc** 取消。格子为 `role="gridcell"` 且有 `id`（`aria-activedescendant` 引用） | `a11y.test.js` 静态断言 + e2e |
| 单一走子逻辑 | 抽出 `_activateSq(sq)`，**鼠标点击与键盘 Enter 共用同一处**（防两套逻辑分叉） | `a11y.test.js` 结构断言 |
| 减少动态效果 | `.fb-danger` 脉动动画尊重 `prefers-reduced-motion` | CSS（既有） |

**设计取舍**：不追求全站合规，只覆盖**核心操作**（走子、弹层按钮、弹层开关）。理由见 §6.3 原文——"核心操作补 role/aria 与键盘操作"，覆盖面按性价比排序。

### 1.2 对比度走查（实测）

用 WCAG 2.1 相对亮度公式实算（`>=4.5:1` 为正文 AA，`>=3:1` 为大字号/图形 AA）。

**深色主题（默认，`--bg:#14161a` / 卡片 `--bg-2:#1e2128`）**

| 用途 | 颜色 | 对比度 | 判定 |
|---|---|---|---|
| 正文 `--text` | `#f2ebd9` | **15.2 : 1** | ✅ AA |
| 次要文字 `--text-dim` | `#8a8f98` | **5.6 : 1** / 卡片上 5.0 | ✅ AA |
| 金 `--gold` | `#c9a227` | **7.5 : 1** | ✅ AA |
| 浅金 `--gold-light` | `#e8c46a` | **10.8 : 1** | ✅ AA |
| 绿 `--green` | `#4caf50` | **6.5 : 1** | ✅ AA |
| 橙 `--orange` | `#e8a33d` | **8.4 : 1** | ✅ AA |
| 红 `--red` | `#b03a2e` | **3.0 : 1** | ⚠️ 仅够大字号 |
| 亮红 `--red-light` | `#e05a47` | **4.9 : 1** | ✅ AA |

→ 深色主题**正文与次要文字全部达标**。唯一注意：`--red` 作**小号文字**色时不足（3.0:1），小字请用 `--red-light`；`--red` 作**背景**（危险按钮底色）时，其上的文字色需自行确认（见下条）。

**亮色主题（`.theme-light`，`--bg:#f4f1ea`）**

| 用途 | 颜色 | 对比度 | 判定 |
|---|---|---|---|
| 正文 `--text` | `#2c2c2c` | **12.4 : 1** | ✅ AA |
| 次要文字 `--text-dim` | `#6b7078` | **4.4 : 1** | ⚠️ 临界（差 0.08） |
| 金 `--gold` | `#b8860b` | **2.9 : 1** | ❌ 小字不达标 |
| 浅金 `--gold-light` | `#a9791a` | **3.4 : 1** | ⚠️ 仅够大字号 |
| 绿 `--green` | `#2e8b57` | **3.8 : 1** | ⚠️ 仅够大字号 |

**待办（真机/人眼）**：亮色主题下，若金色/绿色用于**小号正文文字**，需加深（建议金色文字改用 `#8a6508` 一类，或仅用于 ≥18.66px 粗体 / ≥24px 的标题与图标）。这是一处**已知的、有意留待决策**的点——改动会影响亮色主题的整体观感，需设计确认，故不在本轮擅自改色。

### 1.3 真机 / 人眼走查清单（§6.3）

- [ ] 纯键盘走完一局：Tab 进棋盘 → 方向键选格 → Enter 选中 → 方向键移位 → Enter 落子。
- [ ] 按 Esc 能取消当前选中；升变弹层按 Esc **不**误取消。
- [ ] 屏幕阅读器（NVDA / VoiceOver）朗读棋盘为 grid、格子为 gridcell、活动格随方向键播报。
- [ ] 管理页用户详情弹层：打开后 Tab 焦点在弹层内、Esc 可关、关闭后焦点回到原按钮。
- [ ] 亮色主题下逐一核对金色/绿色文字的可读性（对照 1.2 结论）。

## 二、§6.2 移动端体验

### 2.1 现状盘点（代码层面已具备）

| 能力 | 现状 |
|---|---|
| viewport | 10 个页面**全部**有 `<meta name="viewport" content="width=device-width, initial-scale=1.0">` |
| 触屏热区 | `@media (pointer: coarse)` 下：按钮 ≥42px、驹台棋子用伪元素外扩热区 ≈44px（`style.css` §触屏） |
| 触屏手势 | 棋盘/驹台 `touch-action` 治理，避免"想滚页面却触发拖拽"；`touch-action: manipulation` 防双击缩放 |
| 响应式 | `max-width: 900 / 640px` 两档 + `max-height: 820 / 760px`（矮视口/横屏）多档 |
| 棋盘自适应 | 小屏 `--cell-size` 自动按视口宽度推导（`board.js cellSize()`） |
| 减少动态 | `prefers-reduced-motion` 已处理 |

→ **结论：§6.2 的"代码修补"项在历史迭代中已基本完成**；本项剩余价值在于**真机走查**（原文验收方式即"真机清单全过"）。

### 2.2 真机走查清单（§6.2）

**A. 首屏即见棋盘（对局页 `play.html`）**
- [ ] 手机竖屏打开对局页，**不滚动**即可看到完整棋盘与上方玩家栏。
- [ ] 手机横屏：棋盘完整、无横向溢出（`--cell-size` 是否按 `max-height` 缩小）。
- [ ] 坐标标注开启时（设置里 `showCoords`）不产生横向滚动。

**B. 触屏点选不误触**
- [ ] 两步走子（点选起手驹 → 点目标格）在手机上命中率正常。
- [ ] 棋盘上单指滑动 = 滚页面（不误判为拖拽）；需拖拽时按既有开关行为一致。
- [ ] 驹台棋子单点能选中、不误触发相邻棋子。

**C. 热区 ≥44px**
- [ ] 对局页操作按钮（认输/悔棋式按钮/升变弹层按钮）手指易点中、无"点不到位"。
- [ ] 驹台棋子热区实际约 44px（视觉可更小）。
- [ ] 管理页/赛事页表格里的操作按钮在手机上不被挤成难点。

**D. 横竖屏切换**
- [ ] 对局中旋转屏幕，棋盘与侧栏顺序正确（棋盘在上、侧栏在下）。
- [ ] 旋转后不出现内容被截断或需要横向滚动。

**E. 弹层/弹窗**
- [ ] 升变弹层、赛事创建弹层在手机上完整可见、可滚动、按钮可点。

### 2.3 本清单为何不自动判定

真机走查的每一项都依赖**真实渲染 + 触控采样**：热区是否"点到"、滑动是否"误触"、首屏是否"不被截断"——这些在无头环境里用静态断言无法可信判定（强行断言只会产生"假绿"）。故 §6.2 交付为**可执行清单**，代码侧能自动化的部分（viewport 存在性、`pointer: coarse` 媒体查询存在性）已由既有测试与本文盘点覆盖。
